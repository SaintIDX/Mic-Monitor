  MIC MONITOR v4.0 — Full Feature Guide
═══════════════════════════════════════════════════════════════

WHAT IT DOES
────────────
Mic Monitor sits between your real microphone and other
applications (Discord, Teams, OBS, Zoom). It listens to your
mic in real time and mutes or reduces the output automatically
when the volume gets too loud — for example: handling noise,
bangs on the desk, or sudden shouting. Once the level returns
to normal, audio resumes automatically.

Nothing is recorded or written to disk. No data is sent over
the network. The audio buffer is ~10 ms in RAM and disappears
the moment the program closes.


─────────────────────────────────────────────────────────────
  PART 1 — PREREQUISITES
─────────────────────────────────────────────────────────────

STEP 1: Python
──────────────
1. Go to: https://python.org/downloads
2. Download the latest Python 3.x (Windows installer, 64-bit)
3. Run the installer
   IMPORTANT: check "Add Python to PATH" before clicking
   Install Now — otherwise the next steps will not work
4. Complete the installation


STEP 2: Python libraries
─────────────────────────
1. Open Command Prompt (search "cmd" in the Start menu)
2. Paste and press Enter:

   pip install sounddevice numpy pystray pillow

   (pystray and pillow are needed for system tray support)
3. Wait for: Successfully installed...


STEP 3: VB-Audio Virtual Cable
───────────────────────────────
1. Go to: https://vb-audio.com/Cable/
2. Download "VBCABLE_Driver_Pack43.zip" (or newer)
3. Extract the zip file
4. RIGHT-CLICK "VBCABLE_Setup_x64.exe"
   → Run as administrator
5. Click Install Driver — restart if prompted

VB-Audio Virtual Cable creates two virtual audio endpoints:
  • CABLE Input  — appears as a playback (output) device
  • CABLE Output — appears as a recording (microphone) device

Mic Monitor writes processed audio to CABLE Input.
Discord / Teams / OBS read from CABLE Output.

─────────────────────────────────────────────────────────────
  PART 3 — ROUTING SETUP
─────────────────────────────────────────────────────────────

STEP 5: Select devices in the program
───────────────────────────────────────
  🎤 Input  → your real microphone
              e.g. "Microphone (Realtek Audio)"

  🔊 Output → "CABLE Input (VB-Audio Virtual Cable)"

STEP 6: Set the microphone in Discord / Teams / OBS / Zoom
────────────────────────────────────────────────────────────
In each app, set the microphone to:
  "CABLE Output (VB-Audio Virtual Cable)"

  Discord:  Settings → Voice & Video → Input Device
  Teams:    Settings → Devices → Microphone
  OBS:      Settings → Audio → Mic/Auxiliary Audio
  Zoom:     Settings → Audio → Microphone


─────────────────────────────────────────────────────────────
  PART 3B — VB-AUDIO CONFLICTS & ADVANCED ROUTING
─────────────────────────────────────────────────────────────

IF VB-AUDIO CABLE IS ALREADY IN USE
─────────────────────────────────────
If another application (RTX Voice, Voicemeeter, OBS virtual
cam, etc.) is already writing to CABLE Input, Windows will
MIX both signals together. Discord would hear both the
processed audio from Mic Monitor AND the original unprocessed
signal at the same time — causing echo or doubling.

Solution: install additional virtual cables (free):
  https://vb-audio.com/Cable/  →  download "VBCABLE_A+B"

This gives you Cable A and Cable B as separate channels.
Use Cable A for Mic Monitor, leave Cable B for other apps:

  Microphone  →  Mic Monitor  →  CABLE A Input
                                       ↓
                                 CABLE A Output  →  Discord

No code changes needed — just select the right device
in Mic Monitor's Output dropdown.


CHAINING WITH OTHER AUDIO PROCESSORS
───────────────────────────────────────
If you use RTX Voice, Krisp, or similar noise suppression
alongside Mic Monitor, place Mic Monitor FIRST in the chain
(closest to the raw microphone signal):

  Microphone  →  Mic Monitor  →  CABLE A Input
                                       ↓
                                 CABLE A Output  →  RTX Voice
                                                        ↓
                                                  CABLE Input  →  Discord

This way Mic Monitor gates the raw signal before noise
suppression processes it.


STUDIO MICROPHONES & AUDIO INTERFACES
───────────────────────────────────────
XLR microphones connected via an audio interface (Focusrite,
SSL, Behringer, etc.) appear as standard Windows audio
devices — Mic Monitor works with them the same as any USB mic.

Potential issues and fixes:

  DAW holds the interface in WASAPI exclusive mode
    → Close the DAW, or set Mic Monitor to Standard (MME)
      in Settings → Audio Engine

  Interface only has an ASIO driver (rare)
    → Install the interface manufacturer's WDM driver,
      or install ASIO4ALL (https://asio4all.org)

  Interface is set to 192 kHz or 96 kHz sample rate
    → Lower it to 48 kHz in Windows sound settings:
      Control Panel → Sound → your interface → Properties
      → Advanced → Default Format → 48000 Hz

HEADER

DEVICE DROPDOWNS
─────────────────
  🎤 Input   — your physical microphone
  🔊 Output  — the virtual cable output

  Selections are saved automatically and restored on restart.
  If you switch Audio Mode to WASAPI in Settings, only WASAPI
  devices will appear here.


METER BAR
──────────
  The gradient bar (green → yellow → red) shows the current
  microphone level in real time.

  Blue dashed line  — your calibrated baseline level
                      (where your ambient noise sits)
  Red solid line    — your mute threshold
                      (audio is muted when level crosses this)
  White marker      — peak hold indicator
                      (shows the highest recent level;
                       enabled in Settings → Main Page Widgets)

  Scale below: 0 % = silence, 100 % = maximum signal


BASELINE INFO  /  THRESHOLD INFO  (below the meter)
────────────────────────────────────────────────────
  "Baseline  42 %"  — current adaptive baseline level
  "Threshold  70 %" — current mute threshold

  Both can be hidden in Settings → Main Page Widgets.


MUTE THRESHOLD SLIDER
──────────────────────
  Drag to set the level at which audio is muted or reduced.
  The red line on the meter moves in sync.

  Suggested range:
    30–50 %  very sensitive, mutes easily
    60–75 %  typical use
    80–90 %  only very loud sounds trigger muting

  Tip: calibrate first (press Start, stay quiet 1.5 s),
  then set the threshold so the red line sits clearly above
  the blue baseline line.


START / STOP BUTTON
────────────────────
  ▶ Start monitoring — opens the audio stream and begins
                        the 1.5-second calibration
  ⏹ Stop            — closes the audio stream completely

  While calibrating: stay quiet for 1.5 seconds. The program
  measures the median background noise level and sets it as
  the baseline.


SEND TO TRAY BUTTON
────────────────────
  Hides the main window and keeps the program running in the
  Windows system tray (bottom-right corner of the taskbar).
  Right-click the tray icon to Show window, Start/Stop, Quit.
  Tray icon color matches the status dot.


MINI LOG
─────────
  Shows recent events with timestamps:
    [HH:MM:SS]  Calibration started — stay quiet
    [HH:MM:SS]  Ready — baseline 42 %, threshold 70 %
    [HH:MM:SS]  Level exceeded threshold — output muted
    [HH:MM:SS]  Level recovered — monitoring resumed
    [HH:MM:SS]  Stopped

  Can be hidden in Settings → Main Page Widgets.

MONITORING BEHAVIOR
────────────────────
  Recovery time  (0.5 – 10.0 s, default 2.0 s)
    How long the level must stay below the threshold
    before audio resumes.
    Low value (0.5 s) — resumes very quickly after noise.
    High value (5–10 s) — stays muted longer; useful if
    you have frequent bursts of noise close together.

  Peak hold duration  (0.5 – 5.0 s, default 2.0 s)
    How long the white peak marker stays visible on the
    meter before dropping back to the current level.
    Only relevant when Peak hold indicator is enabled.


AUDIO ENGINE
─────────────
  Audio mode
    ○ Standard (MME)
      Default Windows audio. Works on all systems.
      Latency: ~20–30 ms.

    ○ WASAPI shared
      Windows Audio Session API, shared mode.
      Lower latency (~5–10 ms). Other apps can still
      use the same device simultaneously.

    ○ WASAPI exclusive
      Lowest possible latency (~3–5 ms). The program
      takes exclusive control of the device — other
      apps cannot use it at the same time.
      Use only if you need minimum delay.

    Note: switching to WASAPI mode reloads the device
    list to show only WASAPI-compatible devices.

  Output mode
    ○ Noise gate (mute completely)
      When triggered: output is completely silenced.
      The standard behavior — clean and hard cut.

    ○ Compressor (reduce volume)
      When triggered: output volume is reduced instead
      of silenced entirely. Subtler effect.

    Reduction amount  (0 – 100 %, default 80 %)
      How much the volume is reduced in compressor mode.
      80 % reduction → only 20 % of original volume passes.
      0 % → no reduction (no effect).
      100 % → same as noise gate.
      Only visible when Compressor mode is selected.

─────────────────────────────────────────────────────────────
  PART 7 — SECURITY & PRIVACY
─────────────────────────────────────────────────────────────

• No network connections — verified in the source code.
  Safe to use offline or behind corporate firewalls.
• No audio is written to disk at any point.
• Audio buffer is ~10 ms in RAM; cleared on program close.
• settings.json stores only preferences (no audio data).
• Full source code in mic-monitor-v4-eng.py — every line
  is readable and auditable.
• VB-Audio Virtual Cable is a closed-source kernel driver
  but is widely used, reputable, and free. It does not
  record or transmit audio.


─────────────────────────────────────────────────────────────
  TROUBLESHOOTING
─────────────────────────────────────────────────────────────

"ModuleNotFoundError: No module named 'sounddevice'"
  → pip install sounddevice numpy

"ModuleNotFoundError: No module named 'pystray'"
  → pip install pystray pillow
  → Tray features are optional; the program works without them

Program doesn't hear the microphone
  → Windows Settings → Privacy & Security → Microphone
    → Allow apps to access your microphone → ON
  → Make sure the correct Input device is selected

Other apps (Discord, Teams) can't hear audio
  → In Discord/Teams, set microphone to:
    "CABLE Output (VB-Audio Virtual Cable)"
    NOT "CABLE Input"
  → In Mic Monitor, Output must be:
    "CABLE Input (VB-Audio Virtual Cable)"

Audio sounds slightly delayed
  → Normal: ~10–30 ms added by processing.
    Listeners on the other end are not affected.
  → Try WASAPI shared or exclusive mode for lower latency.

WASAPI mode gives an error on startup
  → Fall back to Standard (MME) in Settings → Audio Engine.
  → Some audio interfaces do not support WASAPI exclusive.

Threshold triggers too easily or too rarely
  → Stop monitoring, wait for silence, start again to
    recalibrate, then adjust the slider.
  → Check that the baseline line (blue) is well below the
    threshold line (red) on the meter.

System tray icon does not appear
  → pip install pystray pillow
  → Restart the program after installing.

Settings are not saved between sessions
  → Check that settings.json can be written to the same
    folder as the .py file (write permission).
